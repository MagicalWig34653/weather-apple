## Flaky ForecastResilience-Ortswechsel (6.11.2026)

Ursache: Testfehler, kein Produktrace. `WeatherStore.select(_:)` startet einen eigenen `Task { refresh() }`; der Test rief zusätzlich `await store.refresh()` auf. Der versteckte Task setzte `generation` neu und verwarf die Antwort des Test-Refresh (Guard `generation == requestID`), dadurch blieb `forecastError` nil (Zeile 161). Reproduziert: Test schlug im Loop bereits in Iteration 1 fehl. Die Produktlogik (Generationsguard, Cache je Ort) verhindert, dass eine veraltete Antwort einen neueren Ort überschreibt. Fix: `select` hält den Task in `selectionRefresh` (nur lesbar), der Test wartet darauf. Belegt: 200 von 200 Läufen grün (auch unter 6 CPU-Lastprozessen), voller Lauf 442 Unit- und 10 UI-Tests grün.
